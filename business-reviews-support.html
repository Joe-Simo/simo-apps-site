Setup guide

Business Reviews talks to Google with your own Google Cloud project and OAuth client. Google lets a project use the Business Profile APIs only after it approves an access request, so plan for that wait before you install.

1. Check that you qualify. Google asks every applicant to manage a Google Business Profile that is verified and active for 60 days or more, with a website listed on the profile. Source: https://developers.google.com/my-business/content/prereqs

2. Request API access. In the Google Cloud console, create or pick a project and copy its Project Number. Submit Google's Business Profile API contact form, choose "Application for Basic API Access" and use an email address that is an owner or manager on your profile. In the console, the Business Profile API quota shows 0 QPM until Google approves the project and 300 QPM after. Source: https://developers.google.com/my-business/content/prereqs

3. Enable the APIs. After approval, enable the Google My Business API, the My Business Account Management API and the My Business Business Information API in the same project. Google shows the Google My Business API only to approved projects. Source: https://developers.google.com/my-business/content/basic-setup

4. Set up the OAuth consent screen. Add the scope https://www.googleapis.com/auth/business.manage and set the publishing status to In production, or use the Internal user type in a Google Workspace organization. Google issues refresh tokens that expire after 7 days to External apps in Testing, so a Testing app stops syncing after a week. Source: https://developers.google.com/identity/protocols/oauth2

5. Create the OAuth client. Create an OAuth client ID of type Web application, add the authorized redirect URI https://oauth.freshdev.io/auth/callback and copy the client ID and client secret.

6. Install the app. Enter the client ID and secret, sign in with the Google account that manages your profile, enter your Freshdesk domain and an admin API key, click Load my locations from Google and tick up to 10 locations. The first sync imports reviews from the last 14 days, then runs every hour.

Frequently asked questions

How often are reviews imported?

Every hour. Each run creates up to 15 new tickets; any extra reviews are created on the next run.

Who is the requester on review tickets?

Google does not share reviewer email addresses, so tickets use the placeholder requester google-reviews@example.com, which never receives mail. The reviewer's name is shown in the ticket. If your helpdesk sends automatic acknowledgement emails, you can exclude this requester in your automation rules.

How do I answer a review?

Send a public reply on the review ticket, or post a draft from the ticket sidebar. The app posts it on Google as the owner reply and adds a private note saying whether Google accepted it. Private notes are never posted.

Why was my reply not posted?

The private note explains the reason: the reply was empty, longer than Google's 4096 byte limit, or Google returned an error. Fix the cause and send the reply again.

What do Google errors mean?

403: the project is not approved yet, an API from step 3 is not enabled, or the signed-in account does not manage the location. 429: the project still has 0 QPM, so wait for Google's approval email. 401: the Google sign-in expired or was revoked, for example a Testing consent screen after 7 days; authorize Google again in the app settings.

What happens when a reviewer edits a review?

The app adds a private note with the new rating and text to the existing ticket instead of creating a new ticket.

What happens when Google rejects an owner reply?

The app adds a private note with the reason Google gives. Send a new public reply to post a different one.
